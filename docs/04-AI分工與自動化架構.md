# 04 AI 分工與自動化架構

> 2026-10-27 更新：Claude Max 附送 API credit（第五部分）；Hermes 和 Claude 的最新規則（第八部分）；多帳戶安排（第十二部分）。

## 一、角色分工
| 角色 | 負責 | 怎樣運行 |
|---|---|---|
| **Claude**（Max 訂閱） | 架構、規劃、重大決定、審查、處理本地模型修不好的問題 | 官方 Claude Code（`claude -p` 自動化） |
| **ChatGPT** | 第二意見、交叉核實重要決定、概念圖 | 經 GitHub app 讀 `studio-kb`；意見寫入 `proposals/` |
| **Codex**（ChatGPT 個人訂閱） | 第一輪程式審查、本地模型失敗後的第二層寫手、寫測試 | `codex exec`，由 orchestrator 呼叫；GitHub PR 的 `@codex review` |
| **本地寫碼模型**（Qwen3.8-27B 或 Qwen3-Coder-Next） | 照任務卡寫程式、跑測試 | Mac Studio 本地伺服器 + Aider |
| **本地視覺模型**（Qwen3.8-27B） | 第一輪看截圖、渲染圖、角色圖並評分 | Mac Studio |
| **雲端 GPU** | 高品質 3D、影片、世界生成 | 按需要租用 |
| **Hermes** | 手機遙控、通知、排程；只把指令放入任務佇列，**不持有 Claude 訂閱登入** | Mac Studio 獨立用戶帳戶 |
| **你** | 定方向、審批重要設計、試玩、判斷好不好玩 | 用 MacBook 或手機遙距 |

## 二、任務流程（已實作）
```
你：plan "目標"
  ↓
Claude 規劃 → 任務卡（寫明檔案、做法、驗收條件；架構決定在這裡定）
  ↓
本地模型在獨立分支寫碼 → 自動測試
  ├ 通過 → 待審查
  └ 失敗 3 次 → 轉交 Codex（2026-10-28 新增）→ 再失敗才轉交 Claude
  ↓
Codex 第一輪審查（找嚴重問題，2026-10-28 新增）
  ↓
Claude 終審（有額度時）
  ├ 批准 → 合併到 develop（2026-10-28 改：不再直接合併 main）
  ├ 退回 → 附意見交回本地模型
  └ 太難 → Claude 親自修；修不好就通知你
  ↓
你每隔幾日用個人 GitHub 帳戶批准 develop → main 的 PR（手機 GitHub app 也可以）
```

## 三、額度用完時
- 偵測 `claude -p` 的額度錯誤訊息，自動冷卻（預設 30 分鐘）並通知你。
- 冷卻期間，本地模型只做已規劃、互相獨立的任務；不作新決定，不合併到 main。
- 有依賴的任務要等前一個審查合併後才開始。所以規劃時盡量拆成互相獨立的任務。
- 額度恢復後：先處理卡住的任務，再逐個審查。
- 預留約三成額度作緩衝；每日 Claude 呼叫上限預設 60 次，留額度給你自己互動用。
- **新選項（2026-10-27，待決）：** 訂閱額度用完時，改用連結組織的 API key 執行 `claude -p`，扣 Max 附送的每月 US$100 API credit，而不是冷卻。要另設每月支出上限；工具包目前會刻意移除 `ANTHROPIC_API_KEY`，要加一個明確的切換開關。

## 四、工具包 `claude-local-orchestrator`
- 檔案：`orchestrator.py`、`config.toml`、`prompts/`（plan、local_task、review、escalate）、`templates/`（launchd 開機自動運行範本）。
- 指令：`plan "目標"`、`run-once`、`loop`、`status`。
- 保護機制：呼叫 Claude 時自動移除 `ANTHROPIC_API_KEY`，確保用 Max 額度；每個任務獨立 git 分支；重試次數和時間上限。
- 已用模擬的 Claude 和本地 agent 完整跑過一次，包括額度用完的情況。
- 已知限制：一次只跑一個任務（避免搶記憶體）；只支援單一工人；額度偵測靠比對錯誤訊息文字；Aider 參數要在 Mac 上用 `aider --help` 確認。
- 待做：支援多工人（MacBook 加入）、圖像和 3D 生成工具的包裝、記憶體排程、讓 Hermes 經任務佇列下指令的介面。

## 五、Claude 方案（2026-10-27 更新）
- Max 5x 每月 US$100；Max 20x 每月 US$200。
- Claude app 和 Claude Code 共用額度，每 5 小時重置；另有每週上限，Anthropic 也可能設其他上限。
- 用完後可以：開啟額外用量、轉用 API 按量付費（Console），或等重置。
- **陷阱：** 系統設定了 `ANTHROPIC_API_KEY` 的話，Claude Code 會用 API key，按 API 收費。
- **Agent SDK 獨立額度（2026-06-15 暫停）已被取代：** 2026-10-07 起，Max 5x 每月附送 **US$100 API credit**，Max 20x 為 US$200（Pro 沒有）。
  - 領取：在 claude.ai 帳單設定連結一個 Claude Console 組織，不需要另加付款方式。有來源指要成為 Max 用戶滿 7 天才可領取（未核實）。
  - 涵蓋：Claude API、Agent SDK、Managed Agents，以及**用連結組織的 API key** 執行的 `claude -p`。
  - 不涵蓋：互動式 Claude Code、Claude app 的額外用量。用訂閱登入執行的 `claude -p` 仍計入訂閱額度，不扣 credit。
  - 每月到期，不可累積。
  - 對我們的意義：等於多一個「合規地用 API key」的預算，可以給第三方工具（例如 Hermes）或額度用完時的後備，但要設支出上限。
- Context：Opus 5.5（2026-09-22 推出）等模型在 Claude Code 有 1M context。1M 是預留空間，不要每次塞滿：太長會影響品質、更快用完額度、更慢。

## 六、Context 管理
- 專案根目錄放 `CLAUDE.md` / `AGENTS.md`：架構、命名規則、測試方法。
- 模組化：檔案要小、界線清楚，本地模型每次只需讀很少檔案。
- 任務卡寫明範圍；每個 session 結束寫交接記錄。
- Claude Code 裡用 `/context` 查用量；一個任務做完就 `/clear`；探索性工作交給子 agent。
- 本地模型每個任務控制在 32K～64K context（Hermes 要求至少 64K）。

## 七、遙距和 24 小時運行
- 網絡：Tailscale（建議用 VPS 做出口節點，取代商業 VPN）。
- 終端：SSH + tmux；VS Code / Cursor Remote-SSH；手機用 Termius 或 Blink。
- 畫面：macOS 螢幕共享（高效能模式）；Mac Studio 插 HDMI 假負載插頭。
- 不睡眠、停電後自動開機、UPS；服務用 `launchd` KeepAlive 自動重啟。
- FileVault 開啟的話，停電重開機要人手解鎖。
- 通知：ntfy、Telegram bot 或 Slack webhook。
- 監察：macmon / asitop；每個任務寫 log。
- 遊戲開發另開一個獨立的 macOS 用戶帳戶。MacBook 上有公司專案，私人項目的 agent 不可以讀取公司的程式碼、憑證和帳戶。

## 八、Hermes Agent（2026-10-27 更新）
- Nous Research 的開源 agent（MIT），支援 macOS 和 Linux，可接本地模型（llama.cpp、MLX、vLLM、LM Studio、Ollama）和 MCP，有訊息閘道、排程任務、子 agent。
- 要求模型至少 64K context，低於 64K 會拒絕啟動。
- 訊息閘道只接受你自己的帳戶；在獨立用戶帳戶下運行。
- **Hermes 和 Claude 訂閱：**
  - Hermes 的 Anthropic OAuth 路線會借用 Claude Code 的登入，並向 Anthropic 自稱 Claude Code。Hermes 官方文件寫明：只在 Max 加購 extra usage 時可用，扣的是 extra usage，不是 Max 本身的額度；Pro 不可以用。
  - Anthropic 2026-04 表示：第三方工具用訂閱不在服務條款允許範圍，自 4 月 4 日起改扣 extra usage；支援頁面寫明這只是「酌情容許」，而冒認身分或企圖把第三方流量計入訂閱額度是禁止的。
  - **Hermes 預設會自動找出並使用 Claude Code 存在 Keychain 的登入。** 要設定 `auth.adopt_external_logins: false`，並讓 Hermes 在沒有 Claude Code 登入的 macOS 用戶下運行。
  - Nous 另有實驗性外掛 Claude Subscription DirectSDK，透過官方 `claude` 執行檔運行，但 Hermes 保留自己的 agent 循環；這種做法是否合規未有定論，**不使用**。
  - 社群有「Claude Code OAuth bypass」之類的修補，偽造請求令 Anthropic 以為是 Claude Code，**絕對不可以用**，有封號風險。
- **我們的做法：** Hermes 的「大腦」用本地模型（或 ChatGPT/Codex 登入）；要 Claude 時，Hermes 只把指令寫入 orchestrator 的任務佇列，由 orchestrator 呼叫官方 `claude -p`。如果真的要 Hermes 直接用 Claude，就用 Max 附送 API credit 的 API key，並設支出上限。

### 官方替代：Claude Code Channels 和 Remote Control（2026-10-27 補充）
用 Max 訂閱額度做手機遙控，官方已經有做法，不需要第三方工具：
- **Channels**（2026-03-20 推出，research preview）：Telegram、Discord、iMessage 的訊息直接送入 Mac Studio 上運行中的 Claude Code session，Claude 用本機檔案、MCP、git 處理後在同一個對話回覆。需要 Claude Code v2.1.80 以上、Bun、claude.ai 的 Pro/Max 登入（不支援 API key）。Team/Enterprise 要管理員開啟。
  - 限制：session 要一直運行（用 tmux 或 launchd）；session 停了，Telegram 訊息會遺失；權限提示會令 session 暫停等你批准；預覽期只接受官方外掛。
- **Remote Control**（`claude remote-control`）：用 claude.ai 或手機 app 直接操作 Mac Studio 上的 session。
- **建議分工：** 24 小時循環仍由 orchestrator + `claude -p` 負責；手機上「查狀態、開新任務、批准」用 Channels 或 Remote Control；通知用 ntfy。Hermes 變成可選。

## 九、VPS 和 VPN
- 長期開商業 VPN 的問題：和 Tailscale 搶路由（kill switch 可能封鎖 Tailscale）、共用 IP 易觸發 Claude 驗證、下載大模型慢。
- 建議：把閒置 VPS 改成 Tailscale 出口節點，固定獨用 IP，出口位置選 Anthropic 支援的地區。可以隱藏位置，但 VPS 供應商知道是你，不算匿名。
- OpenClaw 遷移到 Hermes：先撤銷 VPS 上所有 Claude OAuth token、舊 API key、bot token；建議重裝系統；VPS 沒有 GPU，跑不了本地模型。
- 方案 A（建議先用）：Hermes 放 Mac Studio，VPS 只做出口和看守。
- 方案 B：Hermes 放 VPS，經 Tailscale 指揮 Mac Studio。一定要用 Tailscale ACL 限制 VPS 只能連模型 port 和 SSH 到受限帳戶。
- Claude Code 只在 Mac Studio 上運行，憑證不放 VPS。

## 十一、工具由誰主導（2026-10-11 補充）
- **主導：Claude Code（Max 訂閱，月費固定）。** 不建議以 Claude API 為主，按量收費難以預算。API 只在第三方工具必須用 Claude 時才用，並設每月支出上限（2026-10-07 起可先用 Max 附送的每月 API credit）。
- **Claude Code 不能把自己的「大腦」換成本地模型或其他公司的模型。** Anthropic 官方文件明確表示不支援經 gateway 把 Claude Code 路由到非 Claude 模型。
- **但 Claude Code 可以「指揮」其他工具：**
  - 經 Bash 執行其他 CLI：例如 Codex CLI（`codex exec`）、Aider（接本地模型）。
  - 經 MCP 伺服器：社群有 Codex 的 MCP 伺服器；也可以自己包裝本地模型、Blender、Unity 成 MCP 工具。
  - 子 agent：把探索、搜尋等工作交給子 agent，保持主 session 乾淨。
- **Codex：** 包含在 ChatGPT 方案內（Plus 約每月 US$20 起，已包括 CLI；Pro 有 US$100／200／500 三級），有 5 小時和每週用量上限（2026-10-27：官方頁面指 Pro 目前沒有 5 小時上限，Plus 最強模型每 5 小時約 15～160 則訊息，屬估算）。可以讓 Claude Code 自動叫 Codex 做第二意見的程式審查，把「ChatGPT 作第二意見」自動化。
- **OpenAI 對第三方工具較開放：** 2026-09-29 推出「Sign in with ChatGPT」，參與的第三方工具（例如 OpenClaw、Amp、Devin）可以用 Plus/Pro 的 Codex 額度，用戶可為每個 app 設每週上限。Hermes 是否參與夥伴，未核實。
- **兩種主導方式並存：**
  - 你在線時：Claude Code 互動 session 主導，需要時叫 Codex 或本地模型。
  - 你離開時：`claude-local-orchestrator` 腳本主導 24 小時循環，按規則呼叫 Claude、本地模型。
- **每月訂閱預算（估算）：** Claude Max 5x US$100 + ChatGPT Plus US$20 + Tripo 或 Meshy 約 US$20 + ElevenLabs 約 US$11，合共約 US$150。

## 十二、多帳戶安排（2026-10-27）
帳戶：Claude 兩個（公司、個人）、ChatGPT 一個（個人）、GitHub 兩個（公司、個人）。**技術上全部做得到；問題在條款和隔離。**

**已定（2026-10-28 修正）：** 遊戲項目和私人自動化只用個人帳戶。公司帳戶只做公司工作的自動化排程和審批，完全不作私人用途；可以在 Mac Studio 以獨立 macOS 用戶 `corp` 運行（待公司確認，待決 #16）。兩邊不可以互相接觸的理由：
1. **遊戲 IP 要乾淨。** 用公司付費的帳戶開發私人遊戲，公司可能以「用公司資源開發」主張權利；很多僱傭合約也有知識產權條款。這是最重要的理由。
2. **公司帳戶受公司管理。** Team/Enterprise 帳戶的管理員可以看到用量、對話紀錄，也可以推送設定；私人項目放在那裡，等於交給公司看。
3. **資料外洩。** Agent 權限很大，Hermes 或 Channels 接上 Telegram；公司帳戶接觸公司程式碼，兩者連在一起，公司資料可能流到私人 repo 或訊息平台。公司同意的是「在 MacBook 開發公司專案」，不是讓公司帳戶在無人看管下運行。
4. 反過來也一樣：不要用個人 Max 處理公司程式碼，除非公司同意。

### Claude（兩個登入）
- **技術：** 可以同時運行。最穩妥是每個 Claude 帳戶用一個獨立 macOS 用戶（各自有 Keychain）。同一個用戶下用 `CLAUDE_CONFIG_DIR` 分開設定也是常見做法，但 macOS 上的 OAuth token 存在 Keychain，有工具作者指這樣不能完全隔離，**要實測**。
- **條款，視乎兩個帳戶的用途：**
  | 情況 | 評估 |
  |---|---|
  | 一個私人、一個公司（Team/Enterprise） | 可以。公司帳戶只做公司專案，不放入 24 小時自動化和 Hermes，不放上 Mac Studio（除非公司同意） |
  | 兩個私人訂閱，用來加額度 | **不建議。** 兩個 Max 5x 共 US$200，等於一個 Max 20x 的價錢，但 20x 的額度是 5x 的四倍，兩個 5x 加起來只有兩倍。另外 Anthropic 說 Pro/Max 的額度是按「一般個人用量」設計，並曾因帳戶共用和轉售收緊限制；輪替多個帳戶避開上限有被封風險（未見明文禁止「擁有」兩個帳戶，但「輪替避上限」風險高） |
  | 兩個項目各用一個帳戶 | 技術上可以，但比較同上，一個 Max 20x 通常更划算 |
- **Hermes：** 兩個 Claude 帳戶的訂閱登入都不可以給 Hermes（紅線）。

### ChatGPT（一個登入）
- Mac Studio 上的 Codex CLI 用 ChatGPT 登入：官方做法，可以。
- Hermes 官方支援 ChatGPT／Codex 訂閱登入（device code）。Hermes 文件寫明這個用法怎樣計入 Plus 額度「未有記載」；OpenAI 是否明文容許，未核實。
- **注意：** Hermes 可以借用 Codex CLI 的登入（`~/.codex/auth.json`），刷新 token 時可能令原本的登入失效。建議 Hermes 自己登入一次（`hermes auth add openai-codex`），並設定 `auth.adopt_external_logins: false`。
- Codex CLI 審查和 Hermes 共用同一份 Plus 額度。

### GitHub（兩個登入）
- **GitHub 條款：** 一個人只可以有一個免費個人帳戶，另外可以有一個免費**機器帳戶**，機器帳戶只可以做自動化工作。
- **建議分法：**
  - 你的個人帳戶：擁有 repo、審批、合併 main。只在你自己的 macOS 用戶或 MacBook 登入。
  - 一個機器帳戶（例如 `xxx-bot`）：給 orchestrator 和 agent 用，只有遊戲 repo 的寫入權限（fine-grained token 或 deploy key），**不可以合併 main**；main 設 branch protection，要你的個人帳戶批准。這正好實現「未經審查的程式碼不進 main」。
  - **注意（2026-10-28 核實）：** 私人 repo 的 branch protection 要 GitHub Pro（每月 US$4）或以上，免費帳戶只有公開 repo 有。個人帳戶的 repo 協作者一律有寫入權限，沒有 branch protection 的話，機器帳戶可以直接推上 main。
- 如果第二個是公司的 GitHub 帳戶：GitHub 官方建議工作和私人用同一個個人帳戶，加入公司的 Organization；公司另開的帳戶通常是公司付費或公司管理的帳戶。無論哪種，公司帳戶的憑證不放上 Mac Studio 和 Hermes。

### Mac Studio 用戶帳戶建議
| macOS 用戶 | 放甚麼 | 不放甚麼 |
|---|---|---|
| `factory` | Claude Code（遊戲用 Claude 帳戶）、orchestrator、本地模型、Aider、Codex CLI、GitHub 機器帳戶 token | 你的 GitHub 個人帳戶、公司任何東西 |
| `hermes` | Hermes、訊息閘道 bot token、（可選）ChatGPT 登入、（可選）有支出上限的 Claude API key | 任何 Claude 訂閱登入、GitHub 寫入權限；只能經任務佇列向 orchestrator 下指令 |
| `corp`（2026-10-28 新增，待公司確認） | 公司 Claude（Team/Enterprise）、公司 GitHub 憑證（由公司提供的機器帳戶或 GitHub App）、公司 repo、公司用的 orchestrator | 任何個人帳戶、私人 repo |
| 你的管理員帳戶 | 日常管理、你的 GitHub 個人帳戶、共用的本地模型伺服器 | 不跑 agent |

**私人和公司在同一部 Mac Studio 的設定要點（2026-10-28）：**
- 每個 macOS 用戶的 home 設為 `chmod 700`，互相讀不到檔案；各自有獨立的 Keychain。
- 各自一套 orchestrator、各自的 repo、各自的 Discord bot（或公司用公司的 Slack/Teams）。公司程式碼片段經私人 Discord 傳出去，等於公司資料離開公司系統，要公司同意。
- 本地模型：由管理員帳戶運行**一個**模型伺服器（只綁 localhost），兩邊共用；大型生成器用一個全域鎖排隊，避免兩邊同時載入大模型搶記憶體。工時內公司優先，其餘時間私人優先。
- **陷阱：Keychain 和 24 小時運行。** Claude Code 的登入存在該用戶的 Keychain，該用戶沒有登入 macOS 時，`launchd` 背景服務可能讀不到。做法一：重開機後用螢幕共享逐個用戶登入（快速切換用戶）。做法二：`claude setup-token` 產生長期 token 放入環境變數 `CLAUDE_CODE_OAUTH_TOKEN`；這是官方功能，但有用戶回報 401 錯誤，**要實測**。
- 公司 Claude 是 Team/Enterprise 的話，Channels 要公司管理員開啟（`channelsEnabled`），公司的 managed settings 也會套用到 `corp` 用戶。
- MacBook 同樣分兩個 macOS 用戶：公司用戶和私人用戶。

## 十四、多引擎 orchestrator：Claude + Codex + 本地模型（2026-10-28）

### 設計
把「誰做哪一步」從程式碼抽出來，放入設定檔。每個引擎各自有冷卻計時和每日上限，互不影響。

```toml
# config.toml（設計草稿，未實作）
[engines.claude]
cmd = ["claude", "-p", "--output-format", "json"]
daily_limit = 60

[engines.codex]
cmd = ["codex", "exec", "--json", "--sandbox", "workspace-write"]
daily_limit = 40          # 和你自己用 ChatGPT 共用 Plus 額度，要保守

[engines.local]
cmd = ["aider", "--model", "openai/qwen3-coder-next", "--yes"]

[routing]
plan          = ["claude"]                  # 只有 Claude 做規劃和架構決定
write         = ["local", "codex", "claude"] # 升級階梯：本地失敗 3 次 → Codex → Claude
first_review  = ["codex"]                   # 第一輪：只找嚴重問題
final_review  = ["claude"]                  # 終審：只有 Claude 可以批准合併到 develop
tests         = ["codex", "local"]          # 補測試

[concurrency]
local = 1    # 本地模型一次一個（記憶體）
claude = 1
codex = 1    # 雲端引擎可以和本地同時跑
```

- `codex exec` 預設唯讀，要寫檔案用 `--sandbox workspace-write`；`--json` 輸出事件流，`-o` 把最後訊息寫入檔案，`--output-schema` 可以要求固定 JSON 格式（審查結果適合用這個）。舊的 `--full-auto` 已不支援。
- Codex 讀 `AGENTS.md`；Claude Code 不會直接讀 `AGENTS.md`，要在 `CLAUDE.md` 第一行寫 `@AGENTS.md`。兩者共用同一套專案規則。
- 用 ChatGPT 登入時，`codex exec` 扣 Plus 額度；額度錯誤要像 Claude 一樣偵測並冷卻。

### 參考情景
| 情景 | 流程 | 用到誰的額度 |
|---|---|---|
| **1. 一般夜間** | Claude 規劃 10 張任務卡 → 本地寫 → 測試通過 → Codex 第一輪審查 → Claude 終審 → 合併 develop | Claude：規劃 1 次 + 終審 10 次；Codex：10 次 |
| **2. 本地模型寫不出** | 本地失敗 3 次 → Codex 接手寫（附本地的失敗紀錄）→ 再失敗才交 Claude | 省下 Claude 額度給規劃和終審 |
| **3. Claude 額度用完** | 本地繼續做已規劃的任務；Codex 繼續第一輪審查，通過的標記 `codex-reviewed`；**不合併**，等 Claude 恢復後優先終審（或待決 #12：改用 API credit） | Codex 照用 |
| **4. 補測試** | 每晚為當日合併的模組，由 Codex 寫單元測試和 PlayMode 測試，再走一般審查 | Codex |
| **5. 你在手機開任務** | Discord 傳訊息 → Claude Code Channels（或 Hermes）→ 寫入任務佇列 → orchestrator 下一輪接手 | 規劃用 Claude |
| **6. PR 審查** | develop → main 的 PR 開啟時，GitHub 上 `@codex review` 自動審一次，再由你批准 | Codex（計入哪個額度未核實） |

### Hermes 放 VPS（方案 B）怎樣接上
```
手機 Discord ─→ VPS：Hermes（大腦：ChatGPT 登入，或經 Tailscale 用 Mac Studio 的本地模型）
                     │  只有一個工具：studio-queue（HTTP，帶 token）
                     ▼  Tailscale（ACL 只開 8787 佇列 API 和 1234 模型伺服器）
               Mac Studio：佇列 API（只綁 Tailscale IP）→ orchestrator → claude -p / codex exec / 本地模型
```
- 佇列 API 只提供：查狀態、加任務、暫停、恢復。**不提供批准合併**，批准一律在 GitHub 用你的個人帳戶做。
- VPS 上只有：Hermes 自己的 ChatGPT 登入（或不用，改用本地模型）、Discord bot token、佇列 API token。沒有 Claude 登入、沒有 GitHub 寫入權限。VPS 被入侵，最多只能加任務或暫停。
- Discord：`DISCORD_ALLOWED_USERS` 只放你的 ID（Hermes 預設在沒有名單時拒絕所有人）、`DISCORD_ALLOWED_CHANNELS` 限定頻道、`DISCORD_ALLOW_BOTS` 保持 `none`。
- 方案 A（Hermes 放 Mac Studio `hermes` 用戶）流程相同，只是佇列 API 綁 localhost。
- **ChatGPT 額度：** Hermes 的大腦、`codex exec`、你自己用 ChatGPT 都扣同一份 Plus。Plus 不夠時，Hermes 改用本地模型做大腦（要 64K context）。
- 如果只想手機遙控，Claude Code Channels（Discord）已經足夠，不一定要 Hermes。Hermes 的額外價值：可以放在 VPS（Mac Studio 當機時仍然收到訊息、可以叫醒）、可以用 ChatGPT 或本地模型做大腦、有排程。

### Codex 的工作清單（建議）
1. 第一輪程式審查（每個任務）。
2. 本地模型寫不出時的第二層寫手。
3. 補測試、重現 bug。
4. develop → main PR 的 `@codex review`。
5. Hermes 的大腦（可選）。
6. ChatGPT 本身：第二意見、核實研究、概念圖。
**不給 Codex 的：** 架構決定、規劃、最終批准。這些保留給 Claude 和你，避免兩個「大腦」意見不一時無人拍板。
