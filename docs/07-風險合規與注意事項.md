# 07 風險、合規與注意事項

> 2026-10-27 更新：第一部分加入 Hermes 和 API credit 的最新規則；第五部分改為「私人 MacBook，同時做公司專案」；新增第十部分帳戶規則。

## 一、Claude 使用條款
- Free / Pro / Max 的 OAuth 登入只可以用於 Claude Code 和 Anthropic 自家的 app。不可以放入 Hermes、OpenClaw 或其他第三方工具。
  - Anthropic 2026-01 收緊防止冒認 Claude Code 的保護；2026-02 更新法律與合規頁面；2026-04-04 起，第三方工具用訂閱登入的用量改扣 extra usage，並表明這種用法不在條款允許範圍，只屬「酌情容許」。
  - 冒認身分、企圖把第三方流量計入訂閱額度的工具是明確禁止的（例如社群的「OAuth bypass」修補）。
- 第三方工具要用 Claude，就用 Console 的 API key（按量收費，記得設每月支出上限）。2026-10-07 起，Max 5x 每月附送 US$100 API credit，可以先用這筆。
- 自己的腳本呼叫官方 `claude -p` 是官方文件記載的做法。Anthropic 建議腳本用 `--bare`，並表示將來會成為 `-p` 的預設；`--bare` 模式不讀 OAuth 和 Keychain，**到時要重新檢查訂閱登入的 `claude -p` 是否仍然可用**。
- `claude -p` 在未信任的資料夾也會執行專案的 hooks 和 `.mcp.json`；orchestrator 只在自己的 repo 裡運行，不要讓它進入來歷不明的專案。
- Anthropic 今年多次收緊訂閱的使用範圍，政策可能再變。

## 二、發行和版權
- **Steam：** 玩家看得到、聽得到的 AI 內容（美術、配音、音樂、文本）都要申報；寫程式、測試等幕後工具不用申報。即時生成的內容要有防範不當輸出的措施。
- **美國版權：** 純 AI 生成的內容不受版權保護；只靠 prompt 不足以構成作者身分。經過大幅人手修改的部分，以及整體的編排和選擇，有機會受保護。重要資產要做人手修改並保留記錄。
- Google Play 等平台也有 AI 標示要求。

## 三、模型授權
- Hunyuan3D 2.x：Tencent Hunyuan Community License，**不適用於歐盟、英國和南韓**。
- TRELLIS.2：程式和權重是 MIT，但用到的 DINOv3 有另外的授權，輸出屬「有條件商用」。
- FLUX 系列：不同版本授權不同，部分 dev 版本商用有限制。
- Suno：正面對唱片公司訴訟。
- 免費方案通常不包括商用權利。
- 規則：設立模型白名單，agent 不可以自行上網下載模型放入商業流程。

## 五、MacBook Pro（私人擁有，同時做公司專案）
- MacBook Pro 是本人私人擁有，同時用來開發公司專案，公司已同意；機上沒有公司的 MDM 或監察軟件（2026-10-27 確認）。
- 可以安裝 Tailscale、本地模型、agent，也可以做第二個寫碼工人。
- **仍然要做的：資料分隔。** 部機有公司的程式碼和憑證，而 agent 的權限很大：
  - 私人項目的 agent 在獨立的 macOS 用戶帳戶下運行，不可以讀取公司專案、公司的 GitHub token、SSH key 和鑰匙圈。
  - 公司和私人的 Claude、GitHub 登入分開放在不同用戶。
  - 這不是「公司准不准」的問題，而是保護公司資料、避免自己承擔責任。
- 公開分享截圖前，遮住序號、UUID 等識別資料。

## 六、網絡和安全
- Agent 權限很大：在獨立 macOS 用戶帳戶下運行；訊息閘道只接受自己的帳戶。
- Hermes 設定 `auth.adopt_external_logins: false`，防止它自動借用 Claude Code 或 Codex CLI 的登入。
- VPS：重裝前撤銷所有舊憑證；用 Tailscale ACL 限制存取；不要把 Claude 憑證放上 VPS。
- VPN 出口固定在 Anthropic 支援的地區，避免經常換國家。

## 七、財務
- 每月訂閱預算見 `12-工具預算.md`：規劃期約 US$40，原型期約 US$155，製作期約 US$180～250；另加電費（運行 AI 約 106W，24 小時約 76kWh／月）和雲端 GPU（按需要）。
- 純從省錢角度，本地硬件通常比不上雲端 API。有作者計算，一部約 2 萬美元的 Mac Studio 要連續運行十幾年，產生的 token 才抵得上同等金額的雲端 API。買本地機的理由是：24 小時不受額度限制、私隱、降低對雲端價格和政策的依賴。
- 詳細財務分析在另一個 session 進行。

## 八、從 Sword of the Guardian 學到的 QA 清單（2026-10-11 更新）
由舊作評價拆解得出（詳見 10 第六、七部分），列入自動化測試和審查：
- [ ] 自訂按鍵（鍵盤和手掣）；指令識別的寬容度；搖桿和十字鍵都容易出招
- [ ] 選單流程：任何畫面都可以退回上一層；標題畫面可以退出
- [ ] 存檔：檢查點、自動存檔；測試寫入、讀取、中斷後的完整性；保留備份存檔
- [ ] 章節和路線選擇：通關後可自選章節、路線、角色
- [ ] 戰鬥：攻擊判定、無限連、物品掉落、敵人倒地後的消失時間、畫面外攻擊
- [ ] 場景：上下移動範圍固定；前景物件不遮擋角色（或自動透明）
- [ ] 解像度：超寬螢幕、視窗模式、招式表等介面不被切掉
- [ ] 音效和介面：人聲、打擊聲、血條由 AI 美術總監和試玩者評分
- [ ] 本地化：每種語言由 Claude 審查，並以母語者抽查劇情文本
- [ ] 頭 5 分鐘和頭 1 小時的留存：試玩數據記錄放棄位置
- [ ] 主機版本的檔案大小（Switch 版當年 7.94GB）和載入時間

**續作或重製的額外檢查：**
- 舊美術資產可用於續作；**音樂不可以，要重新製作**。
- 新版本加入 AI 生成內容，Steam 頁面要更新 AI 內容披露。

## 九、開發策略
- 先做垂直切片，跑通整個流程。
- 先定美術聖經（風格、配色、參考圖）。
- 一定要有自動測試，第一個 plan 的目標可以是「建立測試框架」。
- 模型每月更新；硬件買對了，換模型只是下載新檔案。
- 行銷要從開發初期開始：Sword of the Guardian 評價數量和擁有者估計都偏少，中文討論區以負評為主。這次可以早開 Steam 頁面累積願望清單，並用 AI 製作宣傳素材。

## 十、帳戶規則（2026-10-27）
- **Claude：** 不用多個私人訂閱輪替來避開額度上限；需要更多額度就升級方案（Max 20x）。公司的 Claude 帳戶只做公司工作（包括公司工作的自動化排程和審批），不作私人用途。
- **公司工作放在 Mac Studio（2026-10-28）：** 先取得公司同意（之前同意的範圍是 MacBook）；在獨立 macOS 用戶 `corp` 運行；公司程式碼和通知不經私人 Discord，除非公司同意。
- **GitHub：** 一人只可以有一個免費個人帳戶，加一個只做自動化的機器帳戶。Agent 用機器帳戶，權限只限遊戲 repo，不可以合併 main。私人 repo 的 branch protection 要 GitHub Pro。公司的機器帳戶或 GitHub App 由公司提供。
- **共用檔案 repo：** 不放任何密碼、token、VPS IP、帳單資料；用 gitleaks 在 commit 前自動檢查。
- **ChatGPT：** Hermes 自己登入，不借用 Codex CLI 的登入。
