# 14 AI 共用檔案方法

> 2026-10-28 定。所有 AI（Claude Project、ChatGPT、Claude Code、Codex、Hermes、本地模型）讀同一份知識文件，修改只有一個入口。

## 一、整體結構
```
GitHub（個人帳戶，全部私人 repo）
├ studio-kb          知識文件、決策記錄、資產紀錄、其他 AI 的建議   ← 這份文件講的
└ sotg-remake        Unity 遊戲（之後建立，用 Git LFS）；AGENTS.md 指向 studio-kb

Google Drive（現有）
└ 大型原始素材：候選圖、參考圖、3D 原始檔、影片、錄音
```

`studio-kb` 的內容：
```
studio-kb/
├ README.md            給人看：這是甚麼、文件索引
├ AGENTS.md            給所有 AI 的規則（Codex、Hermes 自動讀取）
├ CLAUDE.md            第一行 @AGENTS.md（Claude Code 不會自動讀 AGENTS.md）
├ SETUP.md             建立和連接步驟
├ docs/                01～14 知識文件
├ proposals/           其他 AI 的修改建議，一個建議一個檔案
├ assets/records/      每個 AI 資產一個 JSON：來源模型、授權、Drive 連結
├ .github/             PR 範本
└ scripts/             commit 前檢查有沒有密碼或 token（gitleaks）
```

## 二、Google Drive 和 GitHub 有甚麼分別
| | Google Drive | GitHub |
|---|---|---|
| 最適合 | 大檔案：圖片、3D 原始檔、影片、PSD；給人瀏覽 | 文字、設定、程式、資產紀錄 |
| 版本紀錄 | 每個檔案有舊版本，但看不到「改了哪幾行」，也看不到一批檔案一起改了甚麼 | 每次修改都有逐行差異、說明和作者，可以還原；PR 可以先審後合併 |
| AI 讀取 | Claude 和 ChatGPT 都可以連接；Mac Studio 上的 agent 要另外設定 API | Claude Code、Codex、Hermes 直接 `git clone`；Claude Project 有 GitHub 同步；ChatGPT 有 GitHub app（唯讀） |
| AI 寫入 | 難控制誰改了甚麼 | agent 開分支、開 PR，你批准才合併 |
| 大小 | 容量大 | git 不適合大量二進制；Git LFS 免費只有 10 GiB 儲存和每月 10 GiB 頻寬 |

**結論：兩樣都用，各做擅長的事。**
- 原始素材和大量候選圖留在 Drive。
- 每個資產的「身分證」（來源模型、prompt、授權、修改紀錄，見 07 第四部分）放 GitHub 的 `assets/records/`，寫上 Drive 連結。資產紀錄和決定一起有版本紀錄，日後要證明授權或人手修改時有據可查。
- Unity 實際用到的最終資產放遊戲 repo 的 Git LFS。

## 三、每個 AI 怎樣讀、怎樣寫
| AI | 怎樣讀 | 怎樣寫 |
|---|---|---|
| **Claude Project（claude.ai）** | GitHub integration：揀 `docs/` 和 `AGENTS.md`；**要手動按 Sync** 才更新 | 回答尾的「決策記錄更新」→ 由 Claude Code 開 PR，或你在 GitHub 網頁直接改 |
| **ChatGPT** | GitHub app（唯讀；部分方案只在 deep research 或 agent 模式可用）；不可用時，上傳 `docs/` 的檔案 | 按 `proposals/_template.md` 的格式輸出 → 存入 `proposals/` |
| **Claude Code（Mac Studio、MacBook）** | `git clone`；`CLAUDE.md` 匯入 `AGENTS.md` | 開分支、開 PR |
| **Codex** | `git clone`；自動讀 `AGENTS.md` | 開分支、開 PR；PR 上 `@codex review` |
| **Hermes、本地模型** | `git clone`（唯讀）；Hermes 自動讀 `AGENTS.md` | 不直接寫；要改就經任務佇列交給 orchestrator |
| **你** | GitHub 網頁或手機 app、MacBook | **唯一可以合併 main 的人** |

## 四、規則（已寫入 AGENTS.md）
1. 先讀 `docs/02-決策記錄.md`，它是目前狀態的唯一依據。
2. 任何人（包括 AI）不直接改 main。一律開分支和 PR，由本人合併。
3. 改決定要同時改 `02` 和相關文件，寫明日期和理由。
4. 其他 AI 的意見先寫入 `proposals/`，經「列出假設差異 → 核實事實」後，接納的才改 `docs/`。
5. 有時效的事實（價格、條款、軟件功能）要附來源和核實日期，並更新 `08`。
6. 不放任何密碼、token、VPS IP、帳單資料。
7. 用繁體中文。

## 五、日常流程例子
**例 1：在 Claude Project 討論後有新決定**
1. Claude 回答尾附「決策記錄更新」。
2. 在 Mac Studio 或 MacBook 叫 Claude Code：「把這段決策記錄更新寫入 studio-kb，開 PR」。
3. 你在手機 GitHub app 看差異，批准合併。
4. Claude Project 按 Sync。

**例 2：ChatGPT 給第二意見**
1. ChatGPT 經 GitHub app 讀 `docs/`，按範本輸出建議。
2. 你在 GitHub 網頁 `proposals/` 新增檔案貼上（手機也可以）。
3. 下次在 Claude Project 說「處理 proposals 裡未處理的建議」，Claude 列出假設差異、核實事實，開 PR 修改 `docs/`，建議標記為 accepted 或 rejected。

**例 3：Mac Studio 的 agent 發現文件過時**
1. agent 開分支，修改文件，開 PR，說明來源。
2. 你批准合併。

## 六、實施步驟
**第 0 步（今天，約 10 分鐘）**
1. 用**個人** GitHub 帳戶建立私人 repo `studio-kb`，**不要**勾選加入 README（保持空白）。
2. 把 repo 名稱告訴 Claude，Claude 會連接並推上骨架和全部文件（需要你批准連接）；或者下載骨架 zip，照 `SETUP.md` 自己推上去。
3. 建議升級 GitHub Pro（每月 US$4），設定 main 要經 PR 才可以合併（私人 repo 的 branch protection 要 Pro）。

**第 1 步（推上之後）**
1. Claude Project：加入 GitHub → 揀 `studio-kb` 的 `docs/` 和 `AGENTS.md` → 確認讀得到之後，刪除 Project 裡舊的上傳文件，避免兩份並存。
2. 把 `docs/專案指示-Project-Instructions.md` 的內容貼到 Project 的「Set project instructions」。
3. ChatGPT：設定 → Apps → GitHub → 只授權 `studio-kb`。ChatGPT Project 的指示加一句：「修改建議按 studio-kb 的 proposals/_template.md 格式輸出」。

**第 2 步（Mac Studio 到手）**
1. 開 GitHub 機器帳戶，邀請為 `studio-kb` 和遊戲 repo 的協作者。
2. `factory` 用戶 clone 兩個 repo；執行 `scripts/install-hooks.sh`。
3. 在 Codex 設定開啟 GitHub code review。

## 七、不建議的做法
- 同時在 Claude Project、ChatGPT Project、Drive 各自保留一份可以修改的文件：很快會互相矛盾。
- 讓 agent 直接推上 main。
- 把整個 repo 連同家族故事等私人資料，交給所有 AI 和外掛；按需要揀資料夾授權。

## 八、要注意
- Claude Project 的 GitHub 同步只同步檔案內容，不包括 commit 紀錄和 PR；要手動 Sync。
- ChatGPT 的 GitHub app 是唯讀的，開 PR 要經 Codex 或你。
- 中文檔名在 git 沒有問題；macOS 上設定 `git config --global core.quotepath false`，`git status` 才會顯示中文而不是編碼。
